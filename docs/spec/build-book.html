1 · The model

solago's playbook, rebuilt for Australia.

Solago went from €12,500 in 2022 to about €250M in 2025 by selling brand-name solar online at published prices, with a YouTube channel doing the explaining and no reps or crews. Australia blocks self-install, so we keep everything that transfers and add what it can't do: we're the contracting party, a licensed installer prices the job from photos before payment, and the rebate comes off as a line.

What we sell

  • Batteries first (the price gap is biggest; quote-in-hand buyers are the launch segment), then solar + battery, then EV chargers
  • Brand-only range: SolaX core (1P VAST, 3P X3), Sungrow brand, GoodWe value, Sigenergy premium once CEC-listed; Longi and Risen panels
  • SEQ first, Sunshine Coast installer (Faultless Solar)

How it's priced

  • Hardware: Raystech one-pager cost ÷ 0.75 (25 % margin)
  • Installation: installer cost ÷ 0.9 (10 % margin)
  • GST on the full price, then STCs off as a line at our fixed rate
  • #1002 under this rule: $18,650.31 inc GST − $6,216 rebates = $12,434.31; gross $3,414 (20.1 %); installer paid $4,950. All mockups use this rule; the live build still shows $12,373.81 until Batch 12.
  • Core job 33–40 % under the installed market

Why it wins

  • Published, itemised installed prices that nobody else publishes
  • One contract, one payment, one company for 10 years
  • Installer named and checking the home before payment; instant price for standard homes
  • Content with live postcode prices underneath: a publisher with a shop

Watch → price → secure → confirm → pay → book → own → refer.

1 · Find

A video, article, Shopping ad, creator or referral link lands on a page with a live price for the visitor's postcode (A19, A18, A1, B1).

2 · Convince

Rebate calculator, beat-my-quote, reviews, real installs, the named installer, the guarantee, a person to call (A11–A16, A21, A22, B6).

Product page with size pills, earliest date and every line; save and send to a partner; nurture emails (B1, B5, M9–M12).

Your home → Photos → Price (instant or same day) → Sign + pay (card, or bank −1 %) → Book a real date (C1–E1).

Meet the installer, install-day updates, System Record for life, monthly energy report (E2, E3, F1).

Review at day 14, referral at day 30, share the install, optional filming credit (A21, A24, A22).

7 · System spec

How every page works, not just how it looks.

This chapter is what an agent or developer builds against. It covers the objects the system stores, the states a quote and a job move through (with the page that shows each state), the business rules, a behaviour row for every page (what it reads, what each action does, what it enforces), integrations, the analytics events, and the acceptance tests with real numbers. Each page card links here ("Behaviour spec ↓"), and each row links back to its page.

Ground rules for whoever builds it

  • One source of truth: the Solar Ops code in GitHub. Staging and production environments; nothing reaches production without passing the acceptance tests in 7.7.
  • One builder at a time on the codebase (Claude Code, Lovable or a developer), never two at once.
  • One pricing engine, server-side. Pages never calculate a price themselves; they ask the engine and show the answer.
  • Every money amount comes from a frozen, hashed snapshot once the customer can act on it (secure, sign, pay).
  • Feature flags for every batch; the #1002 path stays the regression test.

Defaults I've taken (change any)

  • Install slips past a rebate change because of us (weather, installer) → we honour the locked rebate. Because the customer reschedules → rebate re-priced, customer told before the new date is confirmed.
  • Referral and creator attribution: the last valid code before "Secure" wins.
  • Bank transfer: 7 days to pay, then the quote is released.
  • Uploaded bills and competitor quotes are deleted after 90 days unless the customer buys. Install photos are kept with the job.
  • Creator commission placeholder: $300 per installed system.

7.3 · Business rules

Price

  • Battery labour is per stack: SVC-BATTERY-INSTALL for the first stack, SVC-BAT-ADD for each additional stack; module count never changes labour.
  • Always margin on sell. Hardware: cost ÷ 0.75 (25 %). Installation and variations: installer cost ÷ 0.9 (10 %). Installer cost = labour menu ÷ 1.1, and that is what the installer is paid.
  • Engine catch-up (Batch 12): the live engine charges installation at menu rate (cost × 1.1, about 9.1 % margin). Moving to ÷ 0.9 adds $60.50 to #1002. The tests in 7.7 use the new rule.
  • Discounts (bank transfer about 1 % of the amount payable, referral $250, report credit $100) reduce the price before GST.
  • GST is on the full price before STCs. STCs come off last as "Less assignment of STCs".
  • #1002: hardware $11,454.83 + installation $5,500.00 = $16,954.83 ex GST; GST $1,695.48; $18,650.31 inc GST; less $6,216; pays $12,434.31. By bank: discount $124.34, GST $1,684.18, pays $12,309.97.

Rebates

  • Solar STCs = floor(zone rating × kWp × deeming years); full kWp with a battery; without a battery, array ≤ 133 % of inverter AC.
  • Battery STCs on CEC usable kWh: 100 % to 14 kWh, 60 % to 28, 15 % to 50, × factor for the install date; one claim per NMI.
  • Value = count × our fixed STC rate (O3), never a live feed.

Rebate window (decided 31 Oct)

  • Rules carry effective dates; the next change date is the window end (31 Dec 2026, then 30 Jun 2027…).
  • Prices shown use the rules for the earliest bookable install date.
  • "Secure this price" at the current rebate is only allowed if a slot exists before the window end. Otherwise the page shows the new-rules price, and that's what's secured.
  • lock_until = earlier of 14 days or the window end. E1 only offers dates before the window end for these quotes.
  • Slip caused by us → we honour it; customer reschedule past the end → re-price first.

Instant price (standard scope)

  • Instant when ALL of: four checks pass · every required photo passes its on-device check · storeys, roof, battery location and switchboard are all in the installer's scope · cable run and travel within limits.
  • Labour = menu lines for the configuration; installer named; scope version stored.
  • Otherwise, to the installer by 5 pm local; missed → next installer for that postcode; none → ops.

Earliest install date

  • = the later of: installer's next free slot (jobs/day, lead days, blackouts) and today + gear lead time for the configuration (supplier stock) + 2 working days.
  • Unpaid quotes never hold a slot. Paid jobs hold a slot 48 h while the customer picks.
  • Over 21 days → shown honestly, and the creator / paid spend throttle triggers (O18).

Cancellation and refunds

  • Within 10 business days of signing: full refund to the original method, no questions.
  • After that, before gear ordered: full refund less any cost we can't recover (agreement sets it).
  • After gear ordered: refund less restocking and freight actually incurred.
  • Every refund: slot released, STC assignment void, Formbay job cancelled, invoice credited in Xero.

Variations

  • Before payment: named lines on D1, accepted with the price.
  • After payment: installer raises in I4 with photos → customer approves on D6 and pays the difference (or gets a refund for removed work). Work in that area pauses until approved.
  • Every variation: installer cost ÷ 0.9 (10 % margin), GST on top.

Referrals and creators

  • Code or link stored on the visitor; the last valid code before Secure attaches to the quote.
  • Referral: $250 off the friend (a discount line) and $250 to the referrer; creator: commission per installed system.
  • Payable only when the job is complete and cooling-off has ended; blocked for the same NMI or email.
  • Every creator post disclosed; O18 checks it.

Privacy and records

  • Bills and competitor quotes: private storage, deleted after 90 days unless the customer buys.
  • Install photos, serials and documents: kept with the job (Formbay/CER record).
  • Record link is a secret; downloads are five-minute signed links; no installer bank details or raw Formbay data on public pages.

8 · Handover pack

Everything a builder needs, with agents as first-class users.

Built by Claude Code from this project, from scratch, at dfrntsolar.com.au. Sections 8.1–8.4 make it AI-first: every capability is an API before it is a screen, so people, agents, or a mix can run any part of the business. Sections 8.5–8.11 are the rest of the handover.

8.1 · AI-first principles

API first, screens second

  • Every action in the page table (7.4) is an API operation. Screens are just one client of that API; agents are another.
  • Published, typed API (OpenAPI) with machine-readable docs, examples and error codes.
  • An MCP server exposes the same operations as tools, so Claude and other agents can work the system directly.

Agents are users

  • Each agent has its own identity, role and scoped key, exactly like a staff member: no shared keys.
  • Every write records who did it (person or agent), why (rationale text) and from what input.
  • Every write takes an idempotency key and supports dry-run ("what would happen").

Humans hold the money and the promises

  • Four permission tiers (8.2). Anything that moves money, changes a price or margin, tells a customer something new, or can't be undone needs a person to approve it in the approvals queue (O22).
  • Agents can propose anything; they can only do what their tier allows.

Everything is an event

  • Every state change in 7.2 publishes an event (8.3) to webhooks and an event log that agents can subscribe to and replay.
  • No logic lives only in a screen; no data lives only in a document.

Plain data, open formats

  • Engine rules, prices, labour menu, rebate schedule, scope rules and content stored as versioned structured data, readable and testable by agents.
  • Exports for every table (CSV/JSON); no lock-in to a vendor screen.

Safe by default

  • Staging copy of the system with test data for agents to practise on.
  • Rate limits and spend caps per agent; kill switch per agent key.
  • Customer-facing AI always says it's AI and hands to a person on request (NETCC: no pressure, honest information).

8.5b · How agents run

The loop

  • Trigger: an event (8.3), a schedule, or a message (chat, SMS, email) starts an Inngest workflow for one agent.
  • Context: the workflow loads only what that agent may read: the record(s) involved, its playbook, the relevant rules and templates.
  • Think + act: Claude runs with the agent's tools (MCP operations at its tiers). Tier A tools execute; tier P tools create a proposal in O22; tier H tools don't exist for agents.
  • Record: every run stores a trace (inputs, tool calls, outputs, cost, time), linked from the audit log and the record it touched.

Memory

  • Agents are stateless between runs: their memory is the system itself (quotes, jobs, tickets, notes, prior traces).
  • Each agent can add an internal note to a record, visible to staff and to itself next time.

Controls (O23)

  • Per agent: on/off, tier per operation, model, monthly spend cap, rate limit, working hours, owner.
